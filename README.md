# ⚽ Football Quant V5.9 — Self-Learning (Streamlit)

วิเคราะห์ตารางราคา 1X2 / Asian Handicap / OU ด้วย Rule 1-26 (+ R27 Coupled Steam, R28 Current Odds Anchor), Home/Away Verification Protocol และ Current Odds Priority ฟันธงเดี่ยว 1 ตัวเลือก
และเรียนรู้จากผลจริง (ปรับน้ำหนัก Rule + สร้าง Rule ใหม่อัตโนมัติ)

## รันในเครื่อง
```bash
pip install -r requirements.txt
export GEMINI_API_KEY=...                # ใช้เฉพาะตอนอ่านรูป (โมเดลเริ่มต้น gemini-3.7-flash)
streamlit run app.py
```
ใช้ผ่านบรรทัดคำสั่งก็ได้: `python football_quant_v58.py --help`

## Deploy บน Streamlit Community Cloud
1. Push โฟลเดอร์นี้ขึ้น GitHub (**ใช้ Private repo ถ้าไม่อยากเปิดเผยโค้ด**)
2. ไปที่ https://share.streamlit.io → New app → เลือก repo/branch → Main file path: `app.py`
3. Advanced settings → **Secrets** วาง:
   ```toml
   GEMINI_API_KEY = "..."
   APP_PASSWORD = "รหัสผ่านของคุณ"
   ```
4. Deploy

## V5.9 มีอะไรเพิ่ม
- **Home/Away Verification Protocol:** ตรวจสิทธิ์เหย้า/เยือนก่อนทุกครั้ง (เรต HDP ปัจจุบัน vs 1X2 ปัจจุบัน, คอลัมน์ซ้ายของตาราง Asian Handicap, ชื่อทีมของ H2H) ถ้าไม่ผ่านจะลดระดับสัญญาณเป็น "ต่ำ"
- **Current Odds Priority:** รายงานแสดงราคาปัจจุบันเป็นหลัก ราคาเปิดใช้อ้างอิงการไหลเท่านั้น และสัญญาณที่มาจากการไหลของราคาล้วน (ไม่มีราคาปัจจุบัน/บริบทหนุน) จะถูกลดคะแนนเหลือ 60%
- **Rule 17-26:** Table Control, Home Pride, High-Scoring Filter, Away Favorite Buffer, Continental Cup Shield, Home Momentum, False Giant Slump Shield
- **Rule 27/28 (เพิ่มเอง):** Coupled Steam Confirmation (เดิมคือ R17 ใน V5.8) และ Current Odds Anchor

ข้อมูลเสริมในไฟล์ JSON (ไม่บังคับ): `rank`, `league_size`, `ah_left_team`, `home_form_home` (`{"w":3,"d":2,"l":0}` ในบ้าน 5 นัด),
`stats.away_counter_pct`, และ context `high_draw_league` / `continental_cup` ดูตัวอย่างใน `example_match.json`

## เก็บข้อมูลถาวร (ซิงก์ GitHub Gist)
ตั้งค่าครั้งเดียว ระบบจะส่งข้อมูลการเรียนรู้ (น้ำหนัก Rule, Rule ที่สร้างเอง, ประวัติ) ไปเก็บที่ Gist ทุกครั้งที่บันทึก และดึงกลับเองเมื่อแอปรีสตาร์ท
1. สร้าง Secret Gist ที่ gist.github.com ไฟล์ `state.json` เนื้อหา `{}` → ได้ `GIST_ID` (รหัสท้ายลิงก์)
2. สร้าง Fine-grained token สิทธิ์ **Gists: Read and write** → `GITHUB_TOKEN`
3. ใส่ทั้งสองค่าใน Secrets ของ Streamlit
- ถ้าไม่ตั้งค่า แอปทำงานเฉพาะในเครื่องเหมือนเดิม
- ถ้าดึงข้อมูลจากคลาวด์ตอนเริ่มไม่สำเร็จ ระบบจะ **ไม่ซิงก์ทับ** จนกว่าจะดึงสำเร็จ (กันข้อมูลบนคลาวด์ถูกเขียนทับด้วยข้อมูลว่าง)
- Secret Gist ไม่อยู่ในรายการสาธารณะ แต่ใครมีลิงก์เปิดอ่านได้ ข้อมูลมีเฉพาะผลวิเคราะห์ ไม่มีรหัสผ่าน/API key
- รันบน VPS/Docker ที่มีดิสก์ถาวรได้โดยตั้ง `QUANT_DATA_DIR` ไม่ต้องใช้ซิงก์

## เก็บข้อมูลถาวรด้วย Google Sheets (แนะนำ)
ใช้ Google Apps Script เป็นตัวกลาง ไม่ต้องสร้าง service account และไม่ต้องติดตั้งไลบรารีเพิ่ม
1. เปิดไฟล์ Google Sheets → **Extensions → Apps Script** → วางโค้ดจาก `apps_script/Code.gs` → แก้ `TOKEN` เป็นรหัสลับของคุณ → Save
2. **Deploy → New deployment → Web app** (Execute as: Me · Who has access: Anyone) → อนุญาตสิทธิ์ → คัดลอก URL ที่ลงท้าย `/exec`
3. ใส่ `SHEETS_URL` และ `SHEETS_TOKEN` (ค่าเดียวกับ `TOKEN`) ใน Secrets ของ Streamlit
- ในไฟล์ชีตจะมีชีต **ประวัติ**, **น้ำหนัก Rule**, **Rule ที่ระบบสร้างเอง** ให้เปิดดูได้ ส่วนชีต `_state` / `_history` ที่ถูกซ่อนไว้คือข้อมูลจริงที่ระบบใช้ **อย่าแก้หรือลบ**
- ระบบกันการเขียนทับ: ถ้าดึงข้อมูลตอนเริ่มไม่สำเร็จ จะไม่ส่งข้อมูลว่างไปทับของเดิม
- แนะนำตั้งการแชร์ไฟล์ชีตเป็น Restricted (ไม่ต้องเปิดลิงก์สาธารณะ)

## ล็อกอินและหมดเวลาเมื่อไม่ได้ใช้งาน
- ตั้ง `APP_PASSWORD` ใน Secrets เพื่อเปิดระบบล็อกอิน เข้าแล้วอยู่ในระบบต่อเนื่อง และ **หมดเวลาเมื่อไม่ได้ใช้งานเกิน 10 นาที** (ปรับได้ด้วย `SESSION_MINUTES = "15"` ใน Secrets)
- โทเค็นล็อกอินอยู่ในลิงก์ (`?s=...`) ฝั่งเซิร์ฟเวอร์ จึงรอดเมื่อมือถือพับแอป/โหลดหน้าใหม่ภายในเวลาที่กำหนด แต่ **อย่าส่งต่อลิงก์ที่มี `?s=`** ให้ผู้อื่นขณะกำลังใช้งาน
- ถ้าเปิดจากไอคอนหน้าจอโฮม/ลิงก์เปล่าที่ไม่มี `?s=` จะต้องใส่รหัสผ่านใหม่ทุกครั้ง
- รีสตาร์ทแอป = ทุกเซสชันต้องล็อกอินใหม่

## หน้าตาแดชบอร์ด
- แสดงผลแบบแดชบอร์ดวิเคราะห์ข้อมูล: ตัวชี้วัดหลัก (สัญญาณ, ความมั่นใจแบบโดนัท, คะแนน, ผลตรวจเหย้า/เยือน), การ์ดแมตช์ (อันดับ ฟอร์ม H2H), ตลาดราคา (1X2 / แฮนดิแคป / สูง-ต่ำ พร้อมกราฟแท่งเทียบราคาเปิด), สกอร์บอร์ดคะแนนต่อทางเลือก และตารางสัญญาณ
- หน้า "บันทึกผล" แสดงแดชบอร์ดเดียวกัน ส่วนหน้า "สถิติ" แสดงอัตราชนะ กำไรต่อไม้ ผลแยกตลาด และน้ำหนัก Rule
- กราฟทั้งหมดเป็น CSS ล้วน (ไม่ใช้ JavaScript/ไลบรารีกราฟ) อยู่ในไฟล์ `dashboard.py`
- ปุ่ม "ดาวน์โหลดรายงานแดชบอร์ด (HTML)" ได้ไฟล์เดี่ยวที่เปิดดู/ส่งต่อได้โดยไม่ต้องใช้แอป
- ไฟล์ที่ต้องอัปขึ้น repo ให้ครบ: `app.py`, `dashboard.py`, `backtest.py`, `football_quant_v58.py`, `requirements.txt`, `.streamlit/config.toml`, `apps_script/Code.gs`

## แก้สกอร์ที่ใส่ผิด
- แท็บ **บันทึกผล → แก้ไขผลที่ใส่ผิด**: เลือกรายการ แก้สกอร์ ติ๊กยืนยัน แล้วกดบันทึก (หรือ "ยกเลิกผล" เพื่อกลับเป็นรอผล)
- หลังแก้ ระบบ **คำนวณการเรียนรู้ใหม่ทั้งหมด** (รีเซ็ตแล้ว replay ทุกนัดตามลำดับที่ใส่ผลเดิม) จึงได้น้ำหนัก Rule และ Rule ที่เรียนรู้เท่ากับกรณีใส่สกอร์ที่ถูกตั้งแต่แรก ไม่มีผลจากสกอร์ผิดค้างอยู่ ทดสอบเทียบแล้วในโค้ด
- ถ้ายกเลิกผลแล้วใส่ผลใหม่ นัดนั้นจะถูกนับเป็นนัดล่าสุดในลำดับการเรียนรู้
- Rule ที่ระบบสร้างเองอาจเพิ่ม/ลด/เปลี่ยนรหัสหลังคำนวณใหม่ (ระบบแสดงสรุปก่อน/หลัง)
- บรรทัดคำสั่ง: `python football_quant_v58.py edit <id> 2-1` และ `python football_quant_v58.py revert <id>`
- ถ้าเปิดซิงก์ Google Sheets/Gist ผลที่แก้จะถูกซิงก์ขึ้นไปด้วย

## ทดสอบย้อนหลัง (Backtest)
แท็บ **ทดสอบย้อนหลัง** เทียบ 3 แบบบนผลที่บันทึกไว้ แบบ walk-forward (ไม่มองอนาคต): **ไม่เรียนรู้** (Rule เดิมตลอด), **เรียนรู้เฉพาะน้ำหนัก**, **เรียนรู้เต็มรูปแบบ** (น้ำหนัก + สร้าง Rule ใหม่)
- ทุกแบบเริ่มจากน้ำหนักเริ่มต้นเท่ากัน เดินทีละนัด: ฟันธงด้วยสถานะ ณ ตอนนั้น → ตัดสินด้วยสกอร์จริง → แบบที่เรียนรู้จึงอัปเดตตัวเอง
- วัด: อัตราชนะ, กำไร/ROI, drawdown สูงสุด, แพ้ติดต่อกัน, ความผันผวน (std), Sharpe-like, สัดส่วนช่วง 10 ไม้ที่กำไร, ROI ครึ่งแรก/ครึ่งหลัง
- ทดสอบนัยสำคัญ 2 ชั้น: bootstrap (ช่วงเชื่อมั่น 95% ของกำไรต่อไม้ที่ต่างกัน) และ **permutation** (สลับสกอร์ระหว่างนัดเพื่อดูว่ากำไรจากการเรียนรู้สูงกว่าความบังเอิญ/โครงสร้างข้อมูลหรือไม่) ต้องผ่านทั้งสองจึงสรุปว่า "ดีกว่า"
- ต้องมีอย่างน้อย 30 นัดจึงสรุปได้ ข้อมูลน้อยจะถูกติดป้าย "น้อยเกินสรุป" · การทดสอบค่อนข้างเข้มงวด จึงมีโอกาสไม่เจอความต่างแม้ความต่างมีจริงเมื่อข้อมูลน้อย
- ดาวน์โหลดรายงานเป็น HTML ได้ · บรรทัดคำสั่ง: `python football_quant_v58.py backtest --perm 100 --html report.html`
